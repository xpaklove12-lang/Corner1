# 문서 길잡이

무엇을 어디에 쓰고 어디서 찾는지 정한다. 작업 전에 이 표에서 해당 폴더를 찾아 읽는다.

| 폴더 | 담는 것 | 규칙 |
|---|---|---|
| [`specs/`](specs/README.md) | 영역마다 그 영역이 무엇이고 어떤 기능을 하는지. 완료된 기능의 기준 | [`CONTRIBUTING.md`](CONTRIBUTING.md)의 규칙과 검사를 따른다. |
| [`tasks/`](tasks/README.md) | 작업마다 목표, 진행 상태(제안, 개발중, 완료), 승인, 할 일, 결과 | [`CONTRIBUTING.md`](CONTRIBUTING.md)의 규칙과 검사를 따른다. |
| [`design/`](design/README.md) | 게임 기획: 한 줄 소개, 핵심 재미, 손님과 회차 구성 | 자유 형식 |
| [`story/`](story/README.md) | 인물 설정, 시나리오, 대사 목록 | 자유 형식 |
| [`art/`](art/README.md) | 아트 방향, 스타일 기준, 애셋 제작 규칙 | 자유 형식 |
| [`tech/`](tech/README.md) | 코드 구조, 데이터 형식 같은 기술 자료 | 자유 형식 |

## 스펙인가 자료인가

- 확인할 수 있는 동작이면 스펙(만들 때는 작업 문서)이다. 예: "걷기 GIF에서 프레임을 뽑아 발 위치를 맞춘다."
- 만들 때 따르는 기준이나 설정이면 자료다. 예: "흑백 선화로 그리고 초상화 특징을 살린다."
- 자료가 바뀌어 게임 동작이 바뀌어야 하면, 그 동작은 해당 스펙에 요구사항으로 더한다.

## 자료 문서 쓰는 법

- 맨 위에 이 문서가 다루는 것을 한 줄로 쓴다.
- 관련 스펙이 있으면 ID로 적는다(예: `FIELD-02`).
- ID, 상태 태그, 양식은 쓰지 않는다. 내용이 생길 때 만들고, 빈 문서를 미리 두지 않는다.
