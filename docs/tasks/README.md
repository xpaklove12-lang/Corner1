# 작업

작업마다 문서 하나를 두고, 진행 상태와 승인을 여기서 관리한다. 이 폴더 바로 아래에는 지금 열려 있는 작업(제안, 개발중)만 있고, 끝난 작업은 [`done/`](done/)에 있다. 폴더만 봐도 무엇이 진행 중인지 보인다.

## 상태와 승인 절차

문서 맨 위 제목 앞의 상태가 곧 승인 단계다.

| 상태 | 뜻 | 다음 단계로 가는 조건 |
|---|---|---|
| `[제안]` | 무엇을 만들지 적었고 승인을 기다린다 | 사용자가 "무엇을 만드나"를 읽고 승인한다 |
| `[개발중]` | 승인되어 만드는 중이다 | 할 일을 다 하고 "확인 방법"대로 확인한다 |
| `[완료]` | 끝났다. 기능을 영역 스펙에 옮겼고 문서는 `done/`에 있다 | 없음. 기록으로 남긴다 |

## 쓰는 법

1. [`_TEMPLATE.md`](_TEMPLATE.md)를 `<첫 ID>-<이번 변경을 나타내는 짧은 영어 이름>.md`로 복사한다(예: `LOC-08-dialogue-translation.md`). 같은 기능을 나중에 다시 고치면 같은 ID로 새 문서를 만들고 이름 뒤쪽만 다르게 짓는다(예: `BURDEN-01-slower-fill.md`). 같은 파일 이름은 쓸 수 없다.
2. ID는 영역 스펙 맨 위의 "다음 번호"를 쓰고, 영역 스펙의 다음 번호를 올린다. 새 영역이면 영역 스펙부터 만든다.
3. "무엇을 만드나"와 "확인 방법"을 쉬운 말로 쓰고 `[제안]`으로 둔다. 이 문서와 번호 변경만 먼저 `dev`에 합쳐 번호를 차지한다.
4. 승인되면 `[개발중]`으로 바꾸고 "어떻게 만드나"와 "할 일"을 쓴다. 할 일은 끝날 때마다 체크한다.
5. 다 만들고 확인하면, 기능을 영역 스펙의 "기능" 절에 반영하고 "코드 단서"를 채운다. 이 문서는 `[완료]`로 바꾸고 "결과"를 쓴 뒤 `done/`으로 옮긴다.

- 문서 하나에 관련된 ID를 여러 개 둘 수 있다(대상 줄에 쉼표로 적는다).
- 완료된 작업 문서는 지우지 않고 고치지도 않는다. 그때 무엇을 왜 그렇게 정했는지 남기는 기록이다. 지금 동작의 기준은 영역 스펙이다.
- 작은 고침(문구 하나 등)은 작업 문서 없이 영역 스펙만 고쳐도 된다.
