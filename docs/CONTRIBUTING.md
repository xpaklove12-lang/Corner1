# 협업 안내

게임이 어떻게 동작해야 하는지는 `docs/specs/`의 영역 스펙이 정하고, 코드는 스펙을 따른다. 지금 개발 중인 것은 [`specs/STATUS.md`](specs/STATUS.md), 스펙 목록은 [`specs/README.md`](specs/README.md), 양식은 [`specs/_TEMPLATE.md`](specs/_TEMPLATE.md), 코드 규칙은 루트 `AGENTS.md`에 있다.

## 작업 순서

1. `specs/README.md`에서 바꾸려는 것의 영역 스펙을 찾아 읽는다. 고칠 요구사항 ID로 "자세히"의 주의도 찾아 읽는다.
2. 그 스펙의 "진행 중"에 요구사항을 `[제안]`으로 쓴다. 번호는 맨 위 "다음 번호"를 쓰고, 다음 번호를 1 올린다.
3. 사용자가 승인하면 `[개발중]`으로 바꾼다. `[개발중]`인 요구사항만 구현한다. 5개를 넘으면 구현 순서를 정해 묶음으로 승인받는다.
4. 구현한 코드에 요구사항 ID 주석을 단다(예: `// BLINK-17: 남은 각도를 화면 오프셋으로 준다.`).
5. 구현을 마치면 그 줄을 "완료"로 옮기고, 상태 태그와 "확인:", "범위 밖:" 줄을 지운다. 고칠 때 깨뜨리기 쉬운 점은 "자세히"의 주의에 남긴다.
6. `Tools/check-specs.ps1 -WriteStatus`로 `specs/STATUS.md`를 다시 만든다.

- 스펙에 없는 동작을 코드에만 넣지 않는다. 구현 중 스펙에 없는 요구가 나오면 멈추고 스펙 수정을 제안한다.
- 스펙이 모호하면 추측하지 않고 묻는다.
- 같은 기능에 새 스펙 파일을 만들지 않는다. 새 스펙은 README에서 맞는 영역이 없을 때만 만든다. `_TEMPLATE.md`를 `영역-이름.md`(소문자 영어, 번호 없음)로 복사하고, 새 대문자 접두어와 함께 README 목록에 등록한다.

## 쓰는 법

- 위쪽(목적, 흐름, 진행 중, 완료)만 읽어도 무엇을 하는지 알 수 있게 쓴다. 고칠 때만 필요한 것은 "자세히"로 내린다.
- 흐름은 Mermaid `flowchart TD` 하나로 그린다. 주요 단계에만 ID를 붙이고, 로직은 차트 아래 두세 문장으로 덧붙인다.
- 요구사항 하나는 확인할 수 있는 동작 하나를 한 문장으로 쓴다("~하면 ~한다"). 예외와 경계 조건은 "자세히 > 주의"에 ID를 앞에 붙여 쓴다.
- 구현 방법은 쓰지 않는다. 클래스 구조, 수치 기본값, 화면 배치는 코드와 Inspector가 기준이다. 제작자가 조절하는 값은 필드 이름으로 가리킨다.
- 코드만 봐서는 알 수 없는 씬 오브젝트 구성과 연결은 "자세히 > 구성"에 쓴다.
- 완료 요구사항은 의도가 아니라 지금 코드가 하는 일을 쓴다. 의도와 달라 보이면 메모에 적는다.
- 확인하지 못한 것은 "확인하지 못함"이라고 쓴다. 추측을 사실처럼 쓰지 않는다.
- CSV 데이터만으로 충족되는 완료 요구사항은 줄 끝에 "(데이터)"를 붙인다. 코드 주석 검사에서 빠진다.
- 진행 중 요구사항에는 "확인:" 한 줄로 Play Mode에서 무엇을 보면 되는지 적는다. 이번에 하지 않을 것이 헷갈리면 "범위 밖:" 줄을 둔다. 테스트 코드는 쓰지 않는다.
- 화면 문구는 `Data/Strings.csv` key나 따옴표 속 글 그대로 적는다. 다른 스펙의 규칙은 ID로 가리킨다(예: `BURDEN-04`).
- 필요 없어진 요구사항은 줄을 지운다. 지운 번호는 다시 쓰지 않는다.
- 변경 이력, 날짜, 작성자는 적지 않는다. 바뀐 내용은 덮어쓴다.

## 작업을 마치면 보고할 것

고친 스펙과 요구사항 ID, ID별 고친 코드, 확인한 방법(컴파일, Play에서 따라 한 절차), 확인하지 못한 것.

## 커밋

- 스펙 작업은 요구사항 ID를 괄호에 쉼표로 잇는다(예: `feat(BLINK-03,MEM-12): 요약`).
- 스펙 없는 정리는 괄호 없이 쓴다(예: `chore: 사용하지 않는 에셋 정리`).

## 규칙 검사

`Tools/check-specs.ps1`이 다음을 본다: 번호 스펙 파일, README 목록에 없는 스펙, 흐름 차트, 접두어 불일치, 중복 ID, 다음 번호 이상인 ID, 진행 중 줄의 상태 태그, 완료 줄에 남은 태그, 낡은 `STATUS.md`, 커밋 제목 괄호 형식. 완료 ID가 코드 주석에 없으면 경고만 한다.

- 커밋 직전 검사: 리포를 받은 뒤 한 번 `git config core.hooksPath .githooks`를 실행한다.
- GitHub 검사: `dev`·`master` 푸시와 PR에서 `spec-check`가 같은 검사를 돌린다.
- 직접 돌리기: `powershell -ExecutionPolicy Bypass -File Tools/check-specs.ps1`
